Configuring Data Lineages
=========================

The DataArts Studio data lineage parsing solution supports automatic lineage analysis and manual lineage configuration. Automatic lineage parsing is recommended. In this mode, lineages can be generated without manual configuration. If automatic lineage parsing is not supported, manually configure lineages.

-  Automatic lineage parsing: Lineages are automatically generated after the system parses the data processing and data migration nodes in data development jobs. No manual configuration is required. For details about the node types and scenarios that support automatic lineage parsing, see :ref:`Automatic Lineage Parsing <dataartsstudio_01_0561__section12458162215283>`.
-  Manual lineage configuration: Customize the input and output tables of lineages in data development job nodes. If you configure lineages manually for a node, the automatic lineage parsing does not take effect for this node. For details about the node types that support manual lineage configuration, see :ref:`Manually Configuring a Lineage <dataartsstudio_01_0561__section123831529241>`.

Constraints
-----------

Currently, field-level lineage parsing is not supported.

.. _dataartsstudio_01_0833__en-us_topic_0000001166742863_section12458162215283:

Automatic Lineage Parsing
-------------------------

Automatic lineage parsing does not require manual configuration. When a data development job contains the nodes and scenarios listed in :ref:`Table 1 <dataartsstudio_01_0833__en-us_topic_0000001166742863_table2038603124620>`, the system can automatically parse lineages.

.. note::

   The lineage of an SQL node can be parsed using multiple SQL statements, and column-level lineage parsing is supported. A single SQL statement cannot contain semicolons (;).

.. _dataartsstudio_01_0833__en-us_topic_0000001166742863_table2038603124620:

.. table:: **Table 1** Job nodes and scenarios that support automatic lineage parsing

   +-----------------------------------------------+-------------------------------------------------------------------------------------------------------+
   | Job Node                                      | Supported Scenario                                                                                    |
   +===============================================+=======================================================================================================+
   | :ref:`DLI SQL <dataartsstudio_01_0450>`       | -  Lineages generated by data insertion between DLI tables                                            |
   |                                               | -  Lineages between OBS files generated by table creation statements and DLI tables                   |
   +-----------------------------------------------+-------------------------------------------------------------------------------------------------------+
   | :ref:`DWS SQL <dataartsstudio_01_0452>`       | Lineages between DWS tables generated by DML operations such as "Insert into"                         |
   +-----------------------------------------------+-------------------------------------------------------------------------------------------------------+
   | :ref:`MRS Hive SQL <dataartsstudio_01_0454>`  | Lineages between MRS tables generated by DML operations such as "Insert into/overwrite"               |
   +-----------------------------------------------+-------------------------------------------------------------------------------------------------------+
   | :ref:`MRS Spark SQL <dataartsstudio_01_0453>` | Lineages between MRS tables generated by DML operations such as "Insert into/overwrite"               |
   +-----------------------------------------------+-------------------------------------------------------------------------------------------------------+
   | :ref:`CDM Job <dataartsstudio_01_0443>`       | Lineages generated during table file migration between MRS Hive, DLI, RDS, OBS, CSS, and GaussDB(DWS) |
   +-----------------------------------------------+-------------------------------------------------------------------------------------------------------+

Manually Configuring a Lineage
------------------------------

In a DataArts Studio data development job, you can customize the input and output tables of lineages on the nodes of the job. If you configure lineages manually for a node, the automatic lineage parsing does not take effect for this node.

The following types of job nodes support manual lineage configuration.

-  :ref:`CDM Job <dataartsstudio_01_0443>`
-  :ref:`Rest Client <dataartsstudio_01_0447>`
-  :ref:`DLI SQL <dataartsstudio_01_0450>`
-  :ref:`DLI Spark <dataartsstudio_01_0451>`
-  :ref:`DWS SQL <dataartsstudio_01_0452>`
-  :ref:`MRS Spark SQL <dataartsstudio_01_0453>`
-  :ref:`MRS Hive SQL <dataartsstudio_01_0454>`
-  :ref:`MRS Presto SQL <dataartsstudio_01_1099>`
-  :ref:`MRS Spark <dataartsstudio_01_0455>`
-  :ref:`MRS Spark Python <dataartsstudio_01_0456>`
-  :ref:`OBS Manager <dataartsstudio_01_0464>`

When manually configuring the lineage, configure the input and output tables of the lineage on the Lineage tab page of the node. The data sources of the input and output tables can be DLI, DWS, Hive, CSS, OBS and CUSTOM. CUSTOM indicates a custom type. When manually configuring a lineage, you can add data sources that are not supported as custom types.


.. figure:: /_static/images/en-us_image_0000002234076044.png
   :alt: **Figure 1** Example of manual configuration of lineage relationships

   **Figure 1** Example of manual configuration of lineage relationships

For example, you need to manually configure a lineage for an MRS Spark node in a pipeline data development job because this node does not support automatic lineage parsing. The procedure is as follows:

#. Log in to the DataArts Studio console by following the instructions in :ref:`Accessing the DataArts Studio Instance Console <dataartsstudio_01_0001>`.

#. On the DataArts Studio console, locate a workspace and click **DataArts Factory**.

#. On the DataArts Factory console, choose **Data Development** > **Develop Job**. Double-click the name of the job for which you want to configure a lineage to open the job canvas.

#. Click the MRS Spark node in the job canvas and then the **lineageInfo** page.


   .. figure:: /_static/images/en-us_image_0000002269115237.png
      :alt: **Figure 2** lineageInfo page

      **Figure 2** lineageInfo page

#. Configure the lineage input table. For example, you can configure input table **hive**, as shown in :ref:`Figure 3 <dataartsstudio_01_0833__en-us_topic_0000001166742863_fig182646316252>`.

   .. _dataartsstudio_01_0833__en-us_topic_0000001166742863_fig182646316252:

   .. figure:: /_static/images/en-us_image_0000002234235876.png
      :alt: **Figure 3** Configuring the lineage input

      **Figure 3** Configuring the lineage input

#. Click **OK** and configure the lineage output table. For example, you can configure output table **a**, as shown in :ref:`Figure 4 <dataartsstudio_01_0833__en-us_topic_0000001166742863_fig553512113282>`.

   .. _dataartsstudio_01_0833__en-us_topic_0000001166742863_fig553512113282:

   .. figure:: /_static/images/en-us_image_0000002234235868.png
      :alt: **Figure 4** Configuring the lineage output

      **Figure 4** Configuring the lineage output

#. Click **OK**. The lineage for the MRS Spark node has been configured. If you want to view the lineage later, collect metadata by referring to :ref:`Viewing Data Lineages <dataartsstudio_01_0834>` and schedule the job. Then, you can view the manually configured lineage of the MRS Spark node in DataArts Catalog.
